# Deliver through explicit capability gates

Build, test, and experience individual teams before extending coordination. This is a staged proposal; native success and human acceptance remain separate.

![Saved definitions are reusable, but only one team runs at a time.](images/team-types.svg)

| Increment | Deliverable | Exit condition |
| --- | --- | --- |
| 1. Native feasibility | Surface/version matrix; small read-only trial in a disposable project. | Sessions/Subagents go/no-go evidence; Teammates marked Deferred until its CLI trial. |
| 2. Sessions agreements and state | Name/questions, CLI writer, saved specifications, claim/recovery, Sessions Focus. | Reuse across two goals; safe switch; no claim of automatic Sessions liveness. |
| 3. Subagents read-only teams | Fresh-session discovery, bounded dispatch, reviewed managed-run recorder setup, observation, integration. | Actual Desktop trial succeeds with restricted workers; otherwise remain unavailable there. |
| 4. Controlled document work | Scoped writes and shared-record serialization, with verified runtime controls. | Out-of-scope denial and preservation tested in a disposable copy. |
| 5. Teammates experiment | CLI in-process team, peer messages, lifecycle evidence. | Separate read-only trial succeeds; enable document work only after its own control checks. |

Application coding, full sprint-hook support, split panes, cross-host coordination, path-reservation infrastructure, and teams of teams are outside v1. Keep Teammates independently withdrawable. Prepare separately reviewed increments/commits; documentation authorization does not authorize committing or deploying them.

Follow the numbered [implementation roadmap](12-implementation-roadmap.md) for assignments and user exercises. The optional document-writing checkpoint may stay Unsupported while independent read-only team trials continue; it is not a prerequisite for a read-only Teammates feasibility trial.

## Gate 1: test the actual surface

Record app/CLI versions, platform, project root, effective settings, native tools, tool restrictions, definition loading, and event coverage. Desktop native agent teams are documented unavailable: do not attempt to label a dynamic workflow Teammates. Offer the CLI experiment as an explicit user choice; if unavailable or declined, preserve the saved definition and mark launch unsupported.

Before a generator exists, Gate 1 uses hand-made, reviewed definitions in a disposable project with a small read-only assignment. Test protected-path writes to `.claude/agents`, `.claude/skills`, settings, and a linked worktree's external common directory, and the user-local host identity path; behavior is surface-dependent. Its event probe uses a hand-made hook only in the disposable project, with reviewed setup and no production hook changes. Every apply preview must provide an exact human-run fallback command if the agent cannot perform it, without weakening runtime protections. Verify existing-directory and first-created-directory behavior, fresh-session discovery, role bootstrap, a denied write, and denied specialist spawning. Exclude shell, mutating MCP tools, and other write-capable routes from read-only worker profiles. Verify the lead's instructed scope as well, explicitly distinguishing it from the worker tool boundary. Do not treat plan mode alone as a write boundary.

Proceed per capability, not an all-or-nothing roster claim. A failed capability stops dependent implementation/launch, while independent Sessions design may continue. This gate establishes a feasible baseline, not permanent vendor guarantees.

## Focused acceptance

- Exercise all typed skills, missing name first, quoted names, cancellation, normalized collisions, opaque IDs, explicit-only invocation, and separate lifecycle parsing. Verify no mutation before the user answers.
- Test preview/token/apply, changed-input rejection, local-edit preservation, deterministic generation, provenance, and fresh-session loading. No implicit commit; no definition repair under an active run.
- Test simultaneous start attempts across worktrees, foreign-host claims and Drive conflict copies, all type-specific ends, incomplete shutdown, manual confirmation, crashed lead, explicit recovery release, stale-event rejection, and ordinary Focus sessions unaffected.
- Run the same saved agreement on two goals with distinct task scopes. Verify correct project/member routing, minimal messages versus durable outputs, and authorized integration.
- Verify control-hook scope and failure behavior: missing executable, crash, timeout, invalid output, and stale/missing member mapping must not silently permit a managed worker write. Out-of-run sessions, unregistered agents, and the lead must remain outside the worker control boundary; if scoped fail-closed behavior cannot be established, keep document work Unsupported/read-only. Verify genuine role/tool denials, multiple independent findings, shared-file handoff, input changes, and serialized review receipts. Document native evidence separately from simulations.
- Prove client routing keeps existing other-client adapters and behavior unchanged; Claude-only skills must not appear there. Validate package/install/update preservation in disposable copies.

## Native Teammates acceptance

After earlier gates, use the supported CLI surface with in-process teammates. Confirm explicit requested type, scoped effective settings, native peer messaging, role body loading, denied worker spawning, and actual shutdown. Test incompatible-mode refusal without changing user-wide settings or silently converting type. A teammate's automatic plan approval is not ASDG human approval.

Measure useful results, user effort, coordination cost, and conflict handling. Prefer a small subset over thirteen workers; warn when more than five teammates are requested. Parallelism is useful only for sufficiently independent work.

## Verification budget and delivery

Run focused checks after relevant changes and the required canonical suite/integrity check per final reviewed implementation increment. Repeat only when subsequent changes invalidate results. Documentation planning uses content, links, receipts, and visual checks, not runtime suites.

Rehearse in disposable sources and clients before Alice. Preserve application files, state, documents, and custom adapters. Review the actual package/adapter/settings effects before any consumer update; native hook trust and a different launch surface remain explicit user choices.

Completion means working named entry points, saved agreements, truthful lifecycle status, one active claim, demonstrated supported modes, and recorded limitations. Unsupported Teammates in Desktop is a valid reported limitation, never a passed native test.
