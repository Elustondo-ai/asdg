Pablo requested the complete replacement command for Claude Code and Codex after reviewing the ownership catalog. ASDG Admin implemented and applied it to the existing Alice, LifeBuckets and Elustondo Web installations. This is a local implementation candidate, not a published release or human-approved document baseline.

## Delivered behavior

The command validates the canonical Git source, distribution hashes, target identity and bounded ownership. It regenerates selected integrations, preserves unrelated content, binds the preview digest, then rechecks under a lock. Backups retain original bytes and modes. Payload verification precedes ownership and review publication; interrupted transactions require recovery before readiness can be reported.

Recovery uses saved before/after states without selecting a newer source. It refuses later user edits. Repeating a successful replacement is a no-op. Malformed JSON, unsafe paths, ambiguous shared syntax, unknown collisions and mismatched executing generators stop application.

Normal client verification recognizes preserved shared settings through validated ownership and reports unfinished transactions. Existing upgrade/init commands keep their conservative contracts. Create Team remains a separate proposal; no native sessions are created by replacement.

## Evidence and limits

The full Python 3.11 suite ran 317 tests: 314 passed and three optional presentation-rendering tests were skipped. Python 3.9 separately passed nine inventory and 22 transaction tests; its Claude preview passed and its Codex preview correctly required a TOML parser. Tests cover both integrations, exact plans, preservation, ownership, interruptions, recovery and no-op behavior.

All three clients match the 483-file package and pass their local status, verification and integrity checks. Each follow-up preview is a no-op. Alice retains both integrations, LifeBuckets retains Claude and Elustondo Web retains Codex. Observed preexisting files outside each transaction are unchanged, as are Git HEADs. The receipt records exact plan IDs, backup paths and verification details.

The diagrams were inspected at a realistic 840-pixel width. A complete rendered Markdown preview was unavailable because the local headless browser aborted; source and embedded assets were reviewed separately. Portable file verification does not establish native skill invocation or hook trust.

Review status remains AI-modified. No commit, push, release, lifecycle transition or approval was performed. The user retains review and commit authority for each repository.
