# Plan ownership-bounded client integrations

[Source: cli_push_integrations.py](cli_push_integrations.py)

Maintainers use this pure planner to replace selected Claude Code and Codex integration units while retaining client instructions, settings and registrations outside those units.

![Selected clients and canonical templates feed adapter rendering and per-client verification.](images/cli_clients-flow.svg)

## Responsibilities and collaborators

- [cli_push](cli_push.md) supplies a validated exact source, bound ownership and client selection, reviews adoption, then applies a transaction; this module never writes.
- [cli_push_inventory](cli_push_inventory.md) validates receipt scope and identity before prior entries reach the planner.
- [cli_clients](cli_clients.md) supplies import recognition and Claude mod runtime names; [cli_project](cli_project.md) supplies current bootstrap, ignore and hook definitions.
- [distribution_files](distribution_files.md) limits source rendering to indexed package members; unindexed skill folders never become write targets.

## Interface

| Callable | Contract |
| --- | --- |
| `integration_plan(root, source, clients, prior_entries)` | Returns `desired` relative file paths mapped to bytes or deletion `None`, exact ownership `entries`, `observations` of inspected file hashes or absence, and `conflicts`. Source is the exact distribution core. Any conflict prohibits applying the entire plan. |
| `integration_problems(root, source, clients, entries=None)` | Reports reconciliation needs using the same ownership-aware planner. Shared TOML and JSON checks accept unrelated settings; native runtime remains unverified. |

Whole adapters and mod files may replace prior-owned bytes, or adopt absent/exact generated bytes and intact installed-version templates through the reviewed plan. Unknown collisions block; exact prior entries alone authorize retirement when source members disappear. No directory deletion occurs.
Bootstrap and ignore blocks require unique complete-line boundaries. Replacement preserves all bytes outside the marked span; bootstrap moves first without trimming user prose. Missing, duplicated, reversed or inline boundaries block. YAML-first bootstrap files require reconciliation.
The selected Claude integration always has an explicit AGENTS import, avoiding dependence on mutable parent instructions. Existing user-written imports remain unmodified and unclaimed. The bridge uses root `CLAUDE.md`, or existing `.claude/CLAUDE.md` when root is absent; a changed prior destination blocks reconciliation to prevent lost ownership.
Codex `features.hooks` is parsed before a minimal textual edit and reparsed to prove unrelated values unchanged. Existing false or malformed user settings without ownership block. Python 3.11+ supplies `tomllib`; Python 3.9/3.10 require `tomli`, otherwise Codex preflight reports `UNSUPPORTED_TOML` before writes.
Hook entries use exact canonical JSON identity inside each event array. Other entries and metadata survive; missing, edited or ambiguous prior identities block instead of guessing ownership. Unidentified ASDG-like commands, including wrong-event registrations, block adoption; recognizable text never establishes ownership. Existing equivalent JSON bytes remain unchanged; a necessary merge may reformat the file.
Symlinked or multiply linked destinations block. Plans carry no timestamps, execute no client code, and grant no hook trust, approval, commit, publication or native session readiness.

## Verification

[Portable integration tests](../../tests/test_push_integrations.md) exercise both clients, preservation, adoption boundaries, idempotence and malformed inputs. A successful result proves generated files and owned semantics only.
